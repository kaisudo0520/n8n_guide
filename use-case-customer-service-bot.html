實用案例：連接 LLM 與知識庫的自動客服機器人

本案例將指導您如何使用 n8n 創建一個智能客服機器人，該機器人結合了大型語言模型 (LLM) 和自定義知識庫，能夠自動回答用戶問題，並在無法解答時轉接真人客服。這種解決方案特別適合希望提高客戶支持效率、降低成本，同時保持高質量服務的企業和組織。

案例概述

自動客服機器人已成為現代客戶支持不可或缺的一部分。然而，傳統的基於規則的機器人往往無法處理複雜或非標準的查詢。通過結合 LLM 的自然語言理解能力和自定義知識庫的專業領域知識，我們可以創建一個更智能、更有效的客服解決方案。

主要功能

  • 多渠道接入：支持網站聊天、Telegram、電子郵件等多種渠道
  • 知識庫整合：使用向量數據庫存儲和檢索相關信息
  • LLM 驅動的回答生成：基於檢索到的信息生成自然、準確的回答
  • 意圖識別：識別用戶意圖，提供針對性的回應
  • 人工轉接：在無法解答或需要人工處理時，智能轉接真人客服
  • 對話管理：維護對話上下文，提供連貫的交互體驗
  • 多語言支持：自動檢測語言並提供多語言回答

技術要求

  • n8n 實例（自託管或雲端）
  • OpenAI API 密鑰（用於 GPT 模型和嵌入生成）
  • PostgreSQL 數據庫（帶 pgvector 擴展）或其他向量數據庫
  • （可選）Telegram Bot API 密鑰
  • （可選）Slack Webhook URL（用於通知）

工作流架構

我們的自動客服機器人系統將分為四個主要部分：

1. 知識庫建立與維護

這部分負責創建和維護機器人的知識基礎：

  • 文檔收集：從多個來源收集知識文檔（FAQ、產品手冊、支持文章等）
  • 文檔處理：分割文檔為適合嵌入的片段
  • 嵌入生成：為每個文檔片段生成向量嵌入
  • 向量存儲：將嵌入和原始文本存儲在向量數據庫中
  • 知識更新：定期更新知識庫以保持信息的準確性和時效性

2. 用戶查詢處理

這部分處理來自各種渠道的用戶查詢：

  • 多渠道接入：接收來自網站、Telegram、電子郵件等渠道的查詢
  • 查詢標準化：將不同渠道的查詢轉換為標準格式
  • 語言檢測：識別查詢的語言
  • 意圖識別：分析用戶意圖（問題、投訴、請求等）
  • 實體提取：識別查詢中的關鍵實體（產品名稱、訂單號等）

3. 知識檢索與回答生成

這部分從知識庫中檢索相關信息並生成回答：

  • 查詢嵌入：為用戶查詢生成向量嵌入
  • 相似度搜索：在向量數據庫中查找相似的文檔片段
  • 上下文組裝：將檢索到的信息組裝為 LLM 的上下文
  • 回答生成：使用 LLM 基於上下文生成回答
  • 回答評估：評估回答的質量和可信度

4. 對話管理與人工轉接

這部分管理對話流程並處理人工轉接：

  • 對話歷史：維護用戶對話歷史
  • 狀態管理：跟踪對話狀態和進度
  • 人工轉接決策：決定何時需要轉接真人客服
  • 通知系統：通知客服人員需要處理的查詢
  • 回覆發送：將回答發送回用戶的原始渠道

// 添加 Function 節點
// 分割文檔為片段
function splitTextIntoChunks(text, maxChunkSize = 1000, overlap = 200) {
  // 如果文本足夠短，直接返回
  if (text.length <= maxChunkSize) {
    return [text];
  }
  
  // 按段落分割
  const paragraphs = text.split(/\n\s*\n/);
  const chunks = [];
  let currentChunk = '';
  
  for (const paragraph of paragraphs) {
    // 如果添加這個段落會超出最大長度，先保存當前片段
    if (currentChunk.length + paragraph.length > maxChunkSize && currentChunk.length > 0) {
      chunks.push(currentChunk);
      
      // 保留一部分重疊內容
      const lastParagraphs = currentChunk.split(/\n\s*\n/).slice(-2);
      currentChunk = lastParagraphs.join('\n\n');
    }
    
    // 添加當前段落
    currentChunk += (currentChunk ? '\n\n' : '') + paragraph;
  }
  
  // 添加最後一個片段
  if (currentChunk) {
    chunks.push(currentChunk);
  }
  
  return chunks;
}

return items.map(item => {
  const text = item.json.text;
  const chunks = splitTextIntoChunks(text);
  
  return {
    json: {
      ...item.json,
      chunks,
      chunkCount: chunks.length
    }
  };
});

3.6 回答評估
// 添加 Function 節點
// 評估回答質量
return items.map(item => {
  const response = item.json.response;
  const hasRelevantContext = item.json.hasRelevantContext;
  
  // 檢查不確定性標記
  const uncertaintyMarkers = [
    "我不確定", "可能", "也許", "我猜", "不太清楚",
    "需要更多信息", "無法確定", "難以判斷", "我不知道"
  ];
  
  let confidenceScore = 0.9; // 默認高信心
  
  // 降低包含不確定性標記的回答的信心分數
  for (const marker of uncertaintyMarkers) {
    if (response.toLowerCase().includes(marker.toLowerCase())) {
      confidenceScore -= 0.2;
      break;
    }
  }
  
  // 如果沒有相關上下文，降低信心分數
  if (!hasRelevantContext) {
    confidenceScore -= 0.3;
  }
  
  // 檢查回答長度是否過短
  if (response.length < 50) {
    confidenceScore -= 0.2;
  }
  
  // 限制最終分數範圍
  confidenceScore = Math.max(0, Math.min(1, confidenceScore));
  
  return {
    json: {
      ...item.json,
      confidenceScore,
      requiresHumanReview: confidenceScore < 0.6
    }
  };
});

// 添加 Function 節點

return items.map(item => {
  // 獲取或初始化對話狀態
  let conversationState = item.json.conversationState || {
    stage: 'initial',
    userData: {},
    pendingActions: [],
    lastInteractionTime: null
  };
  
  // 更新對話狀態
  conversationState.lastInteractionTime = new Date().toISOString();
  
  // 根據當前階段和用戶消息更新狀態
  if (conversationState.stage === 'initial') {
    // 初始階段，檢查是否是問候或特定意圖
    if (item.json.intent === 'greeting') {
      conversationState.stage = 'greeting';
    } else if (item.json.intent === 'question') {
      conversationState.stage = 'question';
    } else {
      conversationState.stage = 'general';
    }
  } else if (conversationState.stage === 'waiting_for_details') {
    // 等待用戶提供更多詳情
    conversationState.userData.details = item.json.message;
    conversationState.stage = 'processing_details';
  } else if (conversationState.stage === 'waiting_for_confirmation') {
    // 等待用戶確認
    const confirmation = isConfirmation(item.json.message);
    if (confirmation === true) {
      conversationState.stage = 'confirmed';
      conversationState.userData.confirmed = true;
    } else if (confirmation === false) {
      conversationState.stage = 'denied';
      conversationState.userData.confirmed = false;
    } else {
      // 用戶回答不明確，保持當前狀態
    }
  }
  
  return {
    json: {
      ...item.json,
      conversationState
    }
  };
});

2. 意圖識別錯誤

問題：機器人可能錯誤識別用戶意圖，導致不適當的回應。

解決方案：

  • 使用更高級的 LLM 模型進行意圖識別
  • 添加意圖確認步驟
  • 實施混合意圖識別方法（規則 + LLM）
  • 收集錯誤案例進行模型微調
// 添加 Function 節點
// 混合意圖識別
function ruleBasedIntentDetection(message) {
  // 簡單規則匹配
  if (/你好|嗨|哈囉|早安|午安|晚安|hi|hello/i.test(message)) {
    return { intent: 'greeting', confidence: 0.9 };
  }
  
  if (/訂單|訂購|購買|買了|下單/i.test(message) && /狀態|進度|何時|到貨|送達/i.test(message)) {
    return { intent: 'order_status', confidence: 0.8 };
  }
  
  if (/退款|退貨|換貨|取消訂單|不要了/i.test(message)) {
    return { intent: 'refund_request', confidence: 0.8 };
  }
  
  if (/價格|多少錢|費用|收費|價錢/i.test(message)) {
    return { intent: 'price_inquiry', confidence: 0.8 };
  }
  
  // 沒有匹配規則，返回 null
  return null;
}

return items.map(item => {
  const message = item.json.message;
  
  // 規則基礎意圖檢測
  const ruleBasedResult = ruleBasedIntentDetection(message);
  
  // LLM 基礎意圖檢測
  const llmBasedIntent = item.json.intent;
  const llmConfidence = item.json.intentConfidence;
  
  // 混合決策
  let finalIntent, finalConfidence;
  
  if (ruleBasedResult && ruleBasedResult.confidence > llmConfidence) {
    finalIntent = ruleBasedResult.intent;
    finalConfidence = ruleBasedResult.confidence;
  } else {
    finalIntent = llmBasedIntent;
    finalConfidence = llmConfidence;
  }
  
  // 如果信心度較低，添加確認步驟
  const needsConfirmation = finalConfidence < 0.7;
  
  return {
    json: {
      ...item.json,
      intent: finalIntent,
      intentConfidence: finalConfidence,
      originalIntent: llmBasedIntent,
      ruleBasedIntent: ruleBasedResult?.intent,
      needsIntentConfirmation: needsConfirmation
    }
  };
});

// 添加 IF 節點
// 條件：{{$json.needsIntentConfirmation}}

// 添加 Function 節點（True 分支）
// 生成意圖確認問題
return items.map(item => {
  let confirmationQuestion;
  
  switch (item.json.intent) {
    case 'order_status':
      confirmationQuestion = '您是想查詢訂單狀態嗎？';
      break;
    case 'refund_request':
      confirmationQuestion = '您是想申請退款或退貨嗎？';
      break;
    case 'price_inquiry':
      confirmationQuestion = '您是想了解價格信息嗎？';
      break;
    default:
      confirmationQuestion = `您是想${intentToQuestion(item.json.intent)}嗎？`;

  return {
    json: {
      ...item.json,
      response: confirmationQuestion,
      awaitingIntentConfirmation: true,
      originalMessage: item.json.message
    }
  };
});

3. 對話上下文丟失

問題：在多輪對話中，機器人可能丟失上下文，導致不連貫的對話體驗。

解決方案：

  • 優化對話歷史管理
  • 實施更智能的上下文窗口滑動
  • 添加對話摘要功能
  • 使用對話狀態追踪
// 添加 Function 節點
// 智能上下文管理
return items.map(item => {
  const history = item.json.conversationHistory || [];
  
  // 如果歷史記錄太長，需要進行摘要
  if (history.length > 10) {

    const recentMessages = history.slice(-3);

  return item;

4. 人工轉接流程問題

問題：人工轉接流程可能不順暢，導致用戶體驗不佳。

解決方案：

  • 優化轉接決策邏輯
  • 添加轉接排隊和狀態更新
  • 實施客服可用性檢查
  • 添加轉接後的跟進機制
// 添加 Function 節點
// 高級轉接決策
return items.map(item => {
  // 基本轉接條件
  let requiresHumanReview = item.json.requiresHumanReview;
  
  // 添加更多轉接條件
  // 1. 用戶明確請求人工客服
  if (/人工|真人|客服|轉接|專員|服務人員/i.test(item.json.message)) {
    requiresHumanReview = true;
  }
  
  // 2. 用戶表達不滿或沮喪
  if (/不滿意|不行|沒用|無法解決|氣死了|生氣|惱火|不幫忙/i.test(item.json.message)) {
    requiresHumanReview = true;
  }
  
  // 3. 多次重複相似問題
  if (item.json.conversationHistory && item.json.conversationHistory.length >= 4) {
    const recentUserMessages = item.json.conversationHistory
      .filter(msg => msg.role === 'user')
      .slice(-3)
      .map(msg => msg.content);
    
    // 檢查最近三條用戶消息是否相似
    if (areSimilarMessages(recentUserMessages)) {
      requiresHumanReview = true;
    }
  }
  
  // 4. 處理敏感問題（如退款、投訴等）
  if (item.json.intent === 'complaint' || 
      item.json.intent === 'refund_request' || 
      item.json.intent === 'account_issue') {
    requiresHumanReview = true;
  }
  
  return {
    json: {
      ...item.json,
      requiresHumanReview
    }
  };
});

結論

通過本案例，我們創建了一個完整的自動客服機器人系統，該系統：

  • 結合了 LLM 的自然語言理解能力和自定義知識庫的專業領域知識
  • 支持多渠道接入，提供一致的用戶體驗
  • 能夠準確識別用戶意圖和提取關鍵實體
  • 基於檢索到的相關信息生成自然、準確的回答
  • 在無法解答或需要人工處理時，智能轉接真人客服
  • 支持多語言，能夠自動檢測語言並提供相應的回答
  • 具有自我學習和改進的能力

這個自動化解決方案可以顯著提高客戶支持效率，降低成本，同時保持高質量的服務。通過減少人工客服處理簡單、重複性問題的時間，使他們能夠專注於更複雜、更有價值的任務。

最重要的是，這個系統不僅僅是一個簡單的問答機器人，而是一個能夠理解用戶需求、提供個性化幫助，並在必要時無縫轉接人工客服的智能助手。它代表了客戶服務自動化的未來方向。
